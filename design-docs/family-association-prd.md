# 家庭关联、身份与权限 PRD

版本：1.0 · 2026-10-22 · 状态：产品方案已确认，独立原型交付，尚未实施业务代码。

## 1. 目标与范围

为宝宝成长录提供从个人建档、关联家庭、申请审批到家庭成员管理的完整闭环。沿用当前微信小程序燕麦色、叶绿色、中性温馨视觉。身份与权限分别展示；家庭记录与媒体不得向未关联用户开放。

P0：个人宝宝档案、创建/加入家庭、身份唯一、邀请审批、身份变更、角色权限、家庭管理、退出/移除/转让、全业务鉴权及已有数据兼容。

不包含：家庭解散、多家庭同时关联、按宝宝分别设置亲属身份、同名宝宝自动合并、真实家庭公开访问、跨家庭迁移历史记录。

## 2. 已确认规则

1. 一个账号最多关联一个有效家庭，一个成员在家庭内只有一种亲属身份。身份按家庭统一。
2. 每种亲属身份只允许一位有效成员；身份可重复申请，但最终占位必须唯一。修改展示称谓不能创建新的身份名额。
3. 爸爸、妈妈默认管理员；爷爷、奶奶、外公、外婆、照护者默认普通成员；其他家人默认只读。
4. 创建者权限独立于亲属身份。仅创建者可授予/撤销管理员、管理管理员、转让创建者；普通管理员仅审批和管理普通/只读成员。
5. 修改展示称谓不改变权限。更换实际身份重新按默认策略计算权限，审批后生效；身份变更前展示权限变化。创建者改亲属身份仍是创建者。
6. 普通成员可新增业务记录、管理本人记录；管理员和创建者可管理全部。只读成员只能查看。
7. 关联前允许创建、更正本人个人宝宝基础档案，不允许新增照护、成长、疫苗、媒体记录。
8. 邀请不是数据访问授权。申请审批前不读取家庭私有数据。
9. 加入已有宝宝家庭时可选择已有宝宝，或将个人档案作为新宝宝归入；不自动合并。普通/只读成员归入个人宝宝须审批。
10. 退出/移除后失去家庭访问权，历史记录留在家庭。创建者须转让后退出。

## 3. 权限模型

| 能力 | 游客 | viewer 只读 | adult 普通 | admin 管理员 | owner 创建者 |
| --- | --- | --- | --- | --- | --- |
| 本人个人基础档案创建/更正 | 是 | 是 | 是 | 是 | 是 |
| 查看家庭数据/获取媒体地址 | 否 | 是 | 是 | 是 | 是 |
| 新增业务记录/上传媒体 | 否 | 否 | 是 | 是 | 是 |
| 修改删除本人记录 | 否 | 否 | 是 | 是 | 是 |
| 修改删除他人记录 | 否 | 否 | 否 | 是 | 是 |
| 家庭宝宝资料/家庭资料管理 | 否 | 否 | 否 | 是 | 是 |
| 邀请、审批普通/只读、移除普通/只读 | 否 | 否 | 否 | 是 | 是 |
| 授予/撤销管理员、管理管理员 | 否 | 否 | 否 | 否 | 是 |
| 退出 | 不适用 | 是 | 是 | 是 | 先转让 |
| 转让创建者 | 否 | 否 | 否 | 否 | 是 |

角色只由服务端有效成员关系得出。前端隐藏操作不替代鉴权。所有成员都只能管理本人展示称谓，管理员不代替本人任意更换亲属身份。

默认身份策略不等于自动授权：加入或变更身份时，审批人确认最终角色；只读/普通权限可由管理员调整。管理员角色只能由创建者授予。身份变更会覆盖此前手工角色配置，须明确提示；创建者身份例外。

管理员可将爸爸/妈妈申请按普通或只读权限批准，但界面明确说明未授予默认管理员权限；若保持默认管理员则转交创建者审批。降级管理员自身的身份变更仍须创建者审批，普通管理员不得绕过对管理员的管理限制。

## 4. 信息架构

- 首次引导：建立个人宝宝档案 / 接受家庭邀请。
- 首页：宝宝信息、家庭身份和权限标签、游客关联提示、申请状态、原业务模块。
- 我的：当前家庭、我的身份、宝宝资料、我的申请。
- 关联家庭：创建家庭 / 输入邀请码或接收邀请链接。
- 创建家庭：名称、亲属身份、选取个人宝宝档案、创建确认。
- 加入家庭：验证邀请、有限预览、可选身份、权限说明、申请提交。
- 申请进度：待审批、通过、拒绝、取消、失效。
- 家庭概览：家庭信息、成员、宝宝、管理入口。
- 家庭成员列表/详情：称谓、身份、角色、可操作范围、权限调整、移除。
- 我的身份：展示称谓编辑 / 实际身份变更。
- 申请管理：加入、身份变更、个人宝宝归入申请。
- 邀请管理：创建、分享、有效期、次数、撤销。
- 家庭设置：家庭名称、退出、创建者转让。无家庭解散。

首页与我的展示完整身份；成长/照护/疫苗使用轻量标签。详情显示作者及权限解释。游客新增入口引导关联；只读新增入口禁用并说明原因。

## 5. 核心流程与状态

### 5.1 启动与个人建档

登录成功 → 获取用户归属和状态 → 有有效家庭则恢复家庭宝宝；无家庭则读取本人个人档案。无档案时允许建档，也可直接接收邀请，避免重复建立宝宝。

状态枚举：initializing、error、guest_no_child、guest_with_child、pending_join、family_no_child、family_ready、identity_required。

权限获取失败不能被解释为游客，需可见错误和重试。无家庭有档案只能看本人基础信息、空状态、公共知识。演示数据单独标明，不混入真实记录。

个人建档必填昵称、出生日期；出生日期不晚于当天。性别可未知，但卫健委生长参考需要完整性别信息。头像媒体上传不在游客阶段开放。

### 5.2 创建家庭

填写名称 → 选择身份 → 选取个人宝宝档案 → 确认归属 → 原子创建家庭、成员、身份占位、账号家庭归属，并关联选中的宝宝。

无个人宝宝可先创建家庭，进入等待完善状态；创建者可添加宝宝。部分失败应回到已有家庭继续完善，不重复创建。

### 5.3 邀请及加入

邀请令牌/邀请码验证 → 最小信息预览 → 身份选择 → 默认权限说明 → 提交申请 → 等待审批 → 成功后家庭宝宝选择。

邀请有限期、撤销状态及使用次数上限。公开预览仅允许展示经选择的家庭名称、可选身份及有效性，不返回宝宝、成员姓名头像、记录、媒体地址。令牌保存摘要，不直接用家庭ID作为授权。

建议生产默认邀请有效期7天、最多10次成功提交；这是可调整的配置默认值。原型为会话内有效的模拟邀请 HOME26，不代表真实令牌。

一个账号仅一条待处理的家庭关联申请；取消、拒绝后可重试。审批时重新验证用户尚无有效家庭、目标身份空闲、邀请和家庭仍有效。待审批不保留身份名额，先完成审批者占位。

### 5.4 审批

申请状态：pending → approved / rejected / cancelled / expired。终态不可重复处理。

审批角色变化前展示最终身份与权限，不能只展示“同意”。创建者审批管理员；管理员审批普通/只读。若身份已占用，申请标记需重选，不覆盖其他成员。申请人不可审批本人申请；创建者本人更换亲属身份为独立的直接确认操作，仍记录审计。

个人宝宝归入申请须校验档案仍归申请人且未关联其他家庭；批准后变为家庭资料，不自动合并，也不携带未知来源业务记录。

### 5.5 身份变更

展示称谓更改立即生效，不改变身份编码/角色。实际身份变更：选择未占用身份 → 对比旧/新角色与能力 → 确认 → 审批 → 原子切换身份占位与角色。旧身份、权限一直保留到成功。

任一旧/新角色为管理员时由创建者处理；其余由管理员或创建者处理。创建者本人可直接确认。不能审批自己的普通成员变更请求。退出、成员移除等使未完成申请失效。

### 5.6 退出、移除、转让

普通/只读/管理员可退出；创建者必须先转让给有效成员。转让前二次确认，接收者变唯一创建者，原创建者变管理员。转让与身份名额无关，不交换亲属身份。

退出、移除立即清除有效成员关联和身份占位，失效相关请求。家庭业务记录、宝宝、媒体和作者ID保留；不复制到个人空间。前端清理家庭数据与媒体地址缓存，返回游客状态；无个人档案时提供建档入口。

移除普通/只读可由管理员执行，移除管理员仅创建者；不能通过移除让家庭失去创建者。

## 6. 业务权限整合

照护、成长、疫苗计划、接种事件、媒体均使用统一能力判断。普通成员的“本人”依据 createdBy/uploadedBy 的稳定用户ID，不依据当前称谓。

疫苗计划与完成接种事件建议拆分作者归属：普通成员可针对家庭计划新增本人接种事件，不可改写他人计划；修改/删除本人事件，不获得他人计划编辑权。该拆分为实现阶段的明确工作项，需兼容现有 vaccines 完成字段，不能直接复制当前成长记录规则而不处理疫苗归属。

媒体获取地址也需鉴权；降权/退出阻止新请求和新写入。已下载或已签发临时地址无法承诺瞬时从设备撤回，应缩短URL有效期、清理前端缓存并配置云存储访问规则。

## 7. 数据设计

复用 users、families、family_members、children、growth_records、vaccines、media_assets。

| 集合 | 扩展字段 |
| --- | --- |
| users | activeFamilyId、lastChildId、membershipVersion |
| families | status(active)、version；保留 ownerId |
| family_members | relationshipCode、relationshipLabel、role(owner/admin/adult/viewer)、permissionSource(identity_default/manual)、version、updatedAt、removedAt |
| children | scope(personal/family)、createdBy、可选familyId、attachedAt、attachedBy、version；保留出生信息 |
| 业务记录 | createdBy、updatedBy、version；按需createdByIdentity快照，不以快照鉴权 |
| vaccines | 审查createdBy完整性；接种事件独立作者及版本 |

新增：

- family_identity_slots：familyId、relationshipCode、memberId、userId、updatedAt。唯一键(familyId,relationshipCode)；释放时删除占位，由审计记录历史。
- family_invitations：familyId、tokenHash、createdBy、expiresAt、maxUses、usedCount、status、version。tokenHash唯一；按家庭/状态/时间查询。
- family_requests：type(join/identity_change/child_attach)、familyId、userId、payload、status、reviewedBy、reviewedAt、reasonCode、version、createdAt、expiresAt。按家庭状态时间、用户状态时间索引。
- family_audit_logs：familyId、actorId、action、targetType、targetId、before、after、requestId、createdAt。客户端不可修改，不保存令牌明文。
- vaccine_completion_events：若采用接种事件分离，familyId、childId、vaccineId、createdBy、completedAt、institution、note、version、deletedAt。

身份默认权限P0服务端版本化常量管理，不额外建立可编辑策略集合。

单账号家庭归属在users文档内以事务校验和更新；family_members保留家庭+用户唯一索引。users.activeFamilyId、成员关系、身份占位、申请状态、归属档案在同一事务边界内更新。不能用“先查询无关联、再写入”的非原子方式保证单家庭。

## 9. 边界、迁移及发布

- 并发加入不同家庭：仅一个成功；另一条申请不可继续授权。
- 同身份并发审批：仅一个成功，另一条提示重新选择；原状态保留。
- 身份变更失败：旧身份和权限完整保留。
- 编辑/上传中被移除：服务端拒绝写入；暂存输入提示不能保存；未关联媒体按清理策略处理。
- 重复提交：相同幂等键返回原结果，不创建重复家庭/申请。
- 姓名相同不合并；退家庭不复制原宝宝；旧作者信息不会随成员删除丢失。
- 旧用户多家庭：不静默删除关系，进入归属整理，由用户选择并按创建者转让规则解除其他关系。
- 旧成员未设置身份：identity_required引导补选，不能自动推断身份。过渡期间保留原有效权限，不因前端显示为空而开放权限。
- 旧家庭重复身份：创建者解决冲突后建立唯一占位；不能直接创建唯一索引导致发布失败或自动移除成员。
- 先备份和检查数据，再部署兼容字段读取、回填、身份补选与唯一约束，最后启用新规则。前后端同步发布；本次不执行真实数据库迁移。

## 10. 验收标准

1. 游客接口不能读取任何家庭业务记录、宝宝详情、媒体URL；只能管理本人个人基础档案。
2. 家庭创建和审批成功后全局身份/权限一致；审批前不能使用家庭写入口。
3. 身份只能占一个名额；并发申请/变更不能产生重复占位或多有效家庭。
4. 爸爸/妈妈默认admin，祖辈/照护者adult，其他家人viewer；创建者不随亲属身份降级。
5. 普通管理员不能授予/移除管理员，普通成员不能改删他人记录，只读不能写。
6. 展示称谓修改不改权限；实际身份审批后角色与名额同时更新，失败保持原状态。
7. 退出/移除后停止访问，原家庭历史数据保留；创建者不能直接退出。
8. 全部加载、失败、无数据、权限失效、申请拒绝和过期状态可见并有下一步。
9. 微信小程序通过lint、格式、类型、云函数打包、build:weapp及真机权限回归。

## 11. 原型说明及验证范围

入口：prototypes/family/index.html。独立HTML/CSS/JS，不修改src或cloud，不包含真实鉴权、上传、事务或审批服务。通过侧栏切换游客、待审批、创建者、管理员、普通、只读场景；使用localStorage保存模拟状态。

模拟审批按钮仅为演示，真实产品不得出现。为便于演示，添加宝宝只填写昵称；生产必须完整填写基础档案。邀请有效期和次数为演示配置。表单记录编辑使用浏览器输入框，生产使用Taro页面/弹窗。

已执行JavaScript语法和模拟DOM核心路径检查；当前无可调用的浏览器控制工具，视觉验收、真实触控、无障碍和微信真机验证未完成。不得把静态检查视为视觉验证。
