# 宝宝成长录：「成长」功能需求文档（两种方案）

版本：评审稿 v1.0　日期：2026-10-21

本文件为需求提案，不表示已实现。两套方案沿用「小树慢慢长」的燕麦白、叶绿色及中性温馨风格。目标用户为共同记录宝宝成长的新手父母和家庭成员。保留首页／成长／相册／我的四个底部导航。

## 1. 目标与当前基础

### 1.1 用户目标

1. 了解宝宝身体测量随时间的变化，方便回看与就诊沟通。
2. 留下第一次、日常能力变化、学习和上学等成长事件，可关联照片与视频。
3. 让不同照护者在同一份档案中补充记录，明确谁在什么时间记录。
4. 从婴儿期持续使用到学龄阶段，不局限于婴儿照护。

成长功能不重复管理喂养、睡眠、排便、健康与疫苗：这些继续归属照护与疫苗模块。旅行和普通家庭影像属于生活记录；只有明确关联成长事件时才在成长中展示同一条记录的引用，不重复创建。

### 1.2 当前代码事实

- 成长页已有身体测量和里程碑两个区块，可切换身高、体重。
- 测量记录使用 measurement；旧 milestone 带 height/weight 时兼容为测量。
- milestone 表示成长事件；study 已有基础新增表单，但成长页未展示。
- school、hobby、award 等仅有领域分类，不等于已经具备完整界面和业务流程。
- 当前曲线按记录序号等距绘点，没有真实时间间距、参考百分位或测量方法区分。
- 首页聚合最多返回最近100条测量，里程碑读取最多100条，不能作为完整历史查询。
- 相册页目前仍是空状态，不能将其视为已经可用的媒体检索模块。
- 现有家庭角色为 owner、adult、viewer。成长页部分入口仅排除 viewer，需改为明确允许 owner/adult，未知角色禁止写入。

### 1.3 共用成功标准

- 测量、里程碑、学习记录均可新增、查询、打开完整详情。
- 成长页、首页「成长数据／最近学会」及记录详情引用同一数据源。
- 分类切换、日期范围、返回状态符合一致规则；只有一个单条详情入口。
- 大量历史记录可继续加载，不以100条静默截断。
- 首版不提供自动诊断、发育排名、强制达标任务或未经验证的健康结论。

## 2. 两种方案对照

| 比较项 | 方案一：成长档案中心 | 方案二：阶段成长故事 |
|---|---|---|
| 首页组织 | 身体测量／成长事件两个工作区 | 当前年龄阶段＋阶段故事时间线 |
| 主要任务 | 快速查数据、记录变化 | 回看阶段、串联事件、家庭共记 |
| 测量入口 | 一级工作区，随时可见 | 阶段内摘要，进入专门测量页 |
| 成长事件 | 里程碑、学习、校园、兴趣分类查询 | 按年龄阶段分组，分类作为筛选 |
| 附件作用 | 记录的辅助证据与回忆 | 故事的主要表现内容之一 |
| 内容稀疏时 | 独立模块仍有明确用途 | 提供简洁阶段空状态，避免空故事墙 |
| 实施成本 | 中，较多复用当前页面与集合 | 较高，需阶段归属、封面、时间线和摘要 |
| 推荐对象 | 优先完善当前产品 | 希望突出长期回忆与家庭情感体验 |

# 方案一：成长档案中心

## A1. 定位与范围

一句话：把身体变化与成长事件整理成能记录、能查询、能回看的家庭成长档案。

一级切换为「身体测量」「成长事件」。「成长事件」下再筛选全部／里程碑／学习／校园／兴趣与收获，不把测量、辅食、疫苗混放在事件类型中。

P0：身高体重、真实时间趋势、测量历史、里程碑与学习、统一详情、新增与编辑删除、日期筛选、分页、权限及异常状态。
P1：校园事件、兴趣与收获、头围、年龄轴、结构化测量方法。
P2：有可靠来源与版本管理的生长参考、成长档案导出。上述能力单独评审，不承诺自动健康判断。

## A2. 页面地图与入口

- 底部「成长」→ 成长档案中心，默认身体测量；宝宝信息区可切换宝宝。
- 首页「查看完整曲线」→ 成长Tab并选中测量工作区。Taro switchTab不依赖query传参，使用一次性导航意图状态，消费后清除。
- 首页「最近学会／查看全部」→ 成长Tab的成长事件工作区，预选里程碑。
- 首页「记录测量／记录新发现」→ 对应新增表单，保存后首页与成长页刷新。
- 新增中心「成长」→ 保留记录类型到子类型的选择；指定上下文的入口直接进入对应表单。
- 成长档案中心 → 测量历史／事件列表 → 单条详情 → 编辑。

## A3. 身体测量工作区

页面从上至下：宝宝名称和年龄 → 工作区切换 → 身高／体重切换 → 最新值与变化 → 日期范围 → 趋势图 → 测量历史入口 → 固定「记录测量」。

### A3.1 最新值及变化

- 身高与体重分别查找最近一条有效值，不强制来自同一记录。
- 明确显示单位、测量日期，以及距上次同指标的变化；例如「80.2 cm，10月21日测量，较上次＋0.8 cm（间隔30天）」。
- 最新值固定表示全历史最新；图表表示所选区间，两者必须标注口径，不能把筛选区间最后一条误称为当前最新。
- 只有一条时不显示增减；没有数据展示「尚未记录」，不能写成0。
- 数值下降正常展示有符号差值，不改成增长、不根据正负直接渲染健康红绿。

### A3.2 日期与图表

- 快捷范围：近3个月、近6个月、近1年、全部；支持自定义起止日期，不允许未来结束日期。
- 横轴按真实测量时间间隔，纵轴含指标与单位；后续支持年龄轴时必须明确轴类型。
- 点击数据点：显示日期、数值、记录人，提供唯一「查看记录」入口。
- 零条：空状态＋新增；一条：显示单点及数值，不绘造假趋势。
- 多条同日：保留所有记录；若发生时间相同，按创建时间与ID稳定排序。
- 缺失身高不补零、不参与身高曲线；体重同理。
- 大数据量可降采样绘图，但必须标明图表为抽样展示；摘要统计和历史列表不能使用降采样结果。
- 不将身长与站立身高不加说明地作医学比较。P0无方法字段时标注「家庭测量趋势」；后续补充方法后显示方法与混用提示。

### A3.3 测量历史

- 按发生时间倒序，日期范围独立可见，筛选保留当前指标。
- 每行展示日期、已有测量值与记录人；缺项用「未填写」或直接不显示该项。
- 按月折叠，默认展开最近一个有记录的月份，支持全开/全关。
- 每页20条并可继续加载，展开分组不能被下一页覆盖或重置。
- 点击整行进入详情，不设置「展开详情」和「完整详情」两个相同概念的按钮。

## A4. 成长事件工作区

页面从上至下：宝宝信息 → 工作区切换 → 日期范围 → 事件类型筛选 → 按日期分组列表 → 固定新增。

- 日期默认近30天，提供近7天、近30天、全部及自定义。
- 里程碑例：第一次翻身、第一次独立行走；学习例：认识新颜色、学会一首儿歌。
- 校园例：入园、开学、毕业；兴趣与收获例：第一次骑车、作品或奖项。P1开启前不显示不可用的空Tab。
- 列表显示标题、类型、发生日期和当时年龄、首张媒体缩略图（有则显示）、记录人。
- 每日可折叠，默认展开最近一天，收起时显示该日事件数。
- P0筛选不要求“已达标／未达标”，记录是发生过的事情，不是儿童能力评分。
- “最近学会”只展示里程碑，学习记录由成长事件显示，不把所有学习内容自动算作第一次。

## A5. 新增、详情与管理

### 测量表单

必填发生日期和时间；身高或体重至少一项。单位固定cm/kg，允许小数。内容与照片选填。正数、数值格式、时间有效性由前后端共同校验。对于疑似误输入，采用确认提示而不是自动修改；具体范围阈值需经产品与专业依据确认，不在本稿随意设定。

P1添加头围、身长/站立身高方法、家庭测量/机构测量来源；旧记录标记方法未记录。

### 事件表单

必填事件类型、标题、发生日期和时间；描述、照片视频选填。显示宝宝当时年龄的只读预览。里程碑允许重复标题，不自动去重；可软提示已有相近事件，并允许继续保存。

标题建议最多50字，描述最多2000字，单条照片与视频混合合计最多10个媒体文件；具体大小、时长上限以统一媒体模块的真实校验和成本配置为准，前后端使用同一配置。

### 详情

结构：类型及记录人 → 标题/测量主值 → 发生时间与当时年龄 → 结构化字段 → 有内容的备注 → 有内容的媒体 → 权限允许的编辑/删除。

- 不显示内部枚举、数据库字段名、空媒体框。
- 图片预览，视频播放；媒体失败展示可重试状态，其余正文照常可读。
- 编辑通过版本校验防止家庭成员互相覆盖；冲突时提示刷新与重新修改，保留本地输入草稿。
- 删除前确认，执行软删除；删除后返回列表并刷新摘要、图表、首页最近事件。原始存储文件按媒体引用关系处理，不能直接删共享文件。
- 取消未保存的编辑有确认；提交期间防止重复点击，失败保留输入。

## A6. 数据及接口建议

复用growth_records和media_assets，不为首页、曲线、事件分别存副本。

- measurement：metrics.height、metrics.weight；P1增加metrics.headCircumference、metrics.measurementMethod、metrics.measurementSource。
- milestone：首次或重要成长事件。
- study：学习变化。
- school：校园事件；hobby和award在前端合并展示为兴趣与收获，存储仍区分类型。
- 通用：familyId、childId、occurredAt、createdBy、updatedAt、deletedAt、mediaFileIds；建议新增version用于并发校验。
- 媒体类型来自media_assets，不通过文件名推断。

建议职责（接口名仅为提案）：

| 接口 | 用途 | 关键返回 |
|---|---|---|
| getGrowthOverview | 当前宝宝成长摘要 | 各指标全历史最新/上次值、最近里程碑 |
| listGrowthMeasurements | 指标和范围查询 | 图表点、口径、是否抽样；历史分页另给游标 |
| listGrowthEvents | 类型/时间筛选分页 | items、nextCursor、hasMore |
| getRecord | 统一详情 | 中文展示所需字段、记录人、媒体类型 |
| createRecord/updateRecord/deleteRecord | 写入及管理 | 服务端归属校验、并发版本、刷新标识 |

列表采用occurredAt＋_id稳定游标，分页按发生时间倒序，不依赖100条一次读取。新记录使用数据库Date；旧字符串时间需要兼容查询或独立迁移，迁移不得擅自修正旧时间。

建议索引复核：familyId＋childId＋category＋occurredAt＋_id，具体排序与查询计划一致；deletedAt过滤是否需纳入索引由云数据库实际执行计划确认。

# 方案二：阶段成长故事

## B1. 定位与范围

一句话：以年龄阶段为章节，将身体测量、第一次与学习经历串成全家共同书写的成长故事。

沿用方案一的原始记录、详情、编辑及权限规则，改变主要浏览方式，不维护另一套重复记录。

P0：阶段导航、阶段时间线、测量摘要、完整测量页、里程碑与学习、记录详情、媒体预览及分页。
P1：校园与兴趣事件、手动精选、阶段封面、家长阶段寄语。
P2：阶段回忆导出。自动成片、生成视频及智能总结不纳入本次范围。

## B2. 阶段与边界

- 0—12个月：按月龄展示章节。
- 1—3岁：按6个月展示章节。
- 3岁及以上：按年龄年展示章节，适配入园及学龄阶段。
- 阶段名称用于整理内容，不表示能力必须在此阶段达成。
- 阶段根据生日和发生日期动态计算；记录本身保留原始发生时间。
- 日期区间采用左闭右开，生日月末采用目标月最后一天；闰日、月末必须使用统一年龄算法。
- 修改生日后重新计算归属并提示用户；不能把阶段ID写死后留下错误归属。
- 生日缺失时提示补全，仍可查看“按日期”的记录列表；未来生日视为档案错误，不显示负年龄。
- 不支持纠正胎龄作为首版能力；后续引入需同时定义孕周数据及年龄口径。

## B3. 页面地图

成长Tab → 阶段成长页 → 阶段选择抽屉 → 阶段记录时间线 → 统一记录详情。

阶段页「身体变化」 → 测量专页（复用方案一身体测量工作区）。
首页完整曲线 → 测量专页；首页最近学会 → 对应里程碑所在阶段并定位该事件。跨Tab仍通过一次性导航意图传递，不依赖switchTab query。

## B4. 阶段成长页结构

1. 宝宝信息：名字、当前年龄、切换宝宝。
2. 阶段标题：例如「1岁—1岁6个月」，并显示具体起止日期；默认选当前阶段。
3. 阶段选择：上/下阶段、全部阶段抽屉；不开放未来阶段新增事件。
4. 阶段摘要：实际记录数、里程碑数、学习记录数；未发生的数据不造数。
5. 身体变化：每个指标显示阶段内最后一次实测及日期，明确不是阶段结束当天测量；可与阶段开始前最近一条同指标对比，必须标注比较日期。
6. 事件时间线：全部／第一次／学习，按发生时间倒序，分月可折叠；每次加载20条。
7. 固定「记录成长」：选择测量、里程碑、学习；从具体模块进入时直接定位类型。

不将喂养、疫苗、旅行全部搬入时间线。生活媒体只有关联事件后才作为事件附件展示。

## B5. 故事呈现与交互

- 有媒体：封面＋标题＋日期＋当时年龄＋记录人，媒体只取代表缩略图，不在滚动时自动播放视频。
- 无媒体：文字条目，不放空封面。
- 里程碑可用「第一次」文字标签，学习用「新进步」标签，不默认生成奖章或连续打卡压力。
- 点击整个事件进入统一详情，不同时提供展开与跳转两种详情操作。
- 查询返回保留阶段、类型、分页和滚动位置。
- 新增允许补记：若发生时间不在当前阶段，保存后提示「已记录到对应阶段」，提供“前往查看”，不能无提示跳走。
- 当前阶段无记录：提供“记录一个新发现”“记录测量”；历史空阶段仍可选，可切换仅显示有记录阶段。
- P1精选是对原记录的引用，删除或权限变化后同步移除，不复制文本与媒体。
- P1阶段封面由有权编辑的成员手选；封面源被删除时回退为阶段标题，不使用失效媒体。
- P1家长寄语独立于宝宝事件，显示作者与更新时间，不自动伪装成宝宝成长事实。

## B6. 数据及接口建议

基础记录继续复用方案一。阶段是查询维度，默认根据child.birthday与occurredAt计算，不为每位宝宝预生成大量空阶段文档。

P0建议接口：

| 接口 | 职责 |
|---|---|
| listGrowthStages | 当前阶段、有内容阶段及对应日期范围 |
| getGrowthStageOverview | 阶段真实计数、测量摘要、更新时间 |
| listGrowthEvents | 按阶段起止日期、类型和游标分页 |
| getRecord及写入接口 | 与方案一共用 |

P1若开启人工编辑的封面和寄语，可新增growth_chapters：familyId、childId、stageStart、stageEnd、birthdayVersion、coverRecordId、coverFileId、message、updatedBy、version、updatedAt。仅保存章节装饰与寄语，不把事件归属以数组复制进章节。

阶段聚合可缓存；生日或记录增删改后失效重算。阶段内“最近测量”与阶段前“基线测量”分别定向查询，不能扫描整个人生记录后取前100条。

## B7. 与方案一的关键取舍

- 测量数据查看多一次进入专页，但情感回顾更突出。
- 阶段算法、生日修改、稀疏内容和媒体布局需要额外验收。
- P0只做真实记录和阶段整理，暂不添加成长任务、能力评估、自动育儿建议。

# 3. 两套方案共用规则

## 3.1 权限

推荐首版策略，需同步到现有写入云函数后才算生效：

| 操作 | owner | adult | viewer/未知角色 |
|---|---|---|---|
| 查看当前家庭宝宝档案 | 是 | 是 | viewer可读；未知需先获取会话 |
| 新增记录 | 是 | 是 | 否 |
| 编辑/删除本人记录 | 是 | 是 | 否 |
| 编辑/删除他人记录 | 是 | 否 | 否 |
| 切换宝宝/筛选/预览媒体 | 是 | 是 | viewer可用 |

所有读写服务端通过WXContext验证身份和家庭成员资格，再校验记录属于当前家庭与宝宝。前端隐藏按钮不能代替服务端授权。该策略为提案，不能误认为当前全部实现；若产品希望adult可协作修改他人记录，应改成明确授权规则并保留审计信息。

## 3.2 状态与数据一致性

- 加载：局部骨架或明确文案，不用旧宝宝数据占位。
- 失败：哪个区域失败哪个区域重试，测量失败不遮蔽已成功加载的事件。
- 无家庭/无宝宝：进入建档引导；只读用户仅提供有权限的操作。
- 切换宝宝：清空旧数据、草稿提示、取消或忽略旧请求返回。
- 新增/编辑/删除成功：刷新受影响模块与首页；失败保留输入，不先显示成功。
- 上传失败：区分文本保存与媒体状态，允许重试或移除失败文件，不静默丢失。
- 返回列表不重置日期、类型、阶段、折叠和已加载分页；数据变化时只修正受影响部分。
- 未配置云环境：保持本地演示回退，同样支持筛选、分页、空状态与权限模拟。
- 生日计算、日期归组使用上海时区；未来事件不能作为已发生里程碑保存。

## 3.3 展示规范

- 页面数据是家庭记录，不呈现发育快慢排名或“落后”标签。
- UI不按宝宝性别使用不同主题。若P2参考曲线需要生理性别等统计参数，应解释用途，未知参数时只显示实际测量趋势。
- 主体文字14—16px，辅助文字不依赖颜色单独传递含义；主操作触控高度至少44px。
- 箭头向右表示跳转；向下/向上仅用于展开收起。
- P0长标题、超长备注和多媒体不挤压日期、数值及主操作，底部操作适配安全区。
- 不为测量缺项、空备注、空附件展示大块白色容器。

## 3.4 标准生长参考的准入（P2）

必须明确参考来源、适用年龄、指标、测量方式、版本、授权及百分位算法；针对来源要求校验参数。不把未知性别/方法强行套入参考线，不用通用BMI结论替代婴幼儿标准。无法满足条件时继续只显示实际趋势，不能用模拟参考线冒充标准。

## 3.5 技术与性能约束

- 微信小程序Taro原生组件，不新增NutUI；通过build:weapp。
- 不在客户端保存服务端凭证；云函数仅经服务层封装调用。
- 列表分页、图表聚合和摘要分工，避免所有历史记录在首页一次读取。
- 建议性能验收目标：正常网络下首屏有内容目标2秒内、翻页目标1秒内；在明确机型、网络和100/1000/10000条记录数据集下实测，未测不能宣称达标。
- 对记录分页请求去重、忽略过期响应；按发生时间和ID稳定排序，避免分页重复或遗漏。

# 4. 验收清单

| 场景 | 方案一验收 | 方案二验收 |
|---|---|---|
| 零条/一条测量 | 无假0、单点可读 | 阶段无测量时不造摘要 |
| 间隔不等的多条测量 | 时间轴间距真实，单位明确 | 测量专页相同标准 |
| 身高体重缺项 | 独立最新值与历史，不补0 | 阶段内分别找值，标记日期 |
| 同日重复测量 | 均保留，可区分时间与作者 | 阶段详情可追溯所有记录 |
| 超过100条 | 分页可查完整记录 | 跨阶段与阶段内分页无遗漏 |
| 旧混合里程碑 | 计入测量、排除技能列表 | 不重复为成长故事 |
| 学习记录 | 新增后在事件页出现 | 出现在发生时间对应阶段 |
| 2月末/闰日/跨年 | 年龄与日期展示正确 | 阶段边界无重复无漏记 |
| 补记历史事件 | 按发生日期归组 | 提示实际所属阶段，可前往 |
| 编辑/删除 | 曲线、列表、首页同步 | 阶段计数与封面引用同步 |
| 详情返回 | 保留筛选、分组与滚动 | 保留阶段、分页及滚动 |
| 只读/跨家庭请求 | UI与云函数同时限制 | 同左 |
| 切换宝宝时旧请求晚回 | 不覆盖新宝宝数据 | 不污染新宝宝阶段 |
| 图/视频失败 | 正文保留，可重试 | 不显示失效封面，不阻塞列表 |
| 未配置云环境 | 演示流程可完成 | 演示阶段流程可完成 |

新增测试应优先覆盖时间归属、跨家庭隔离、分页边界、单位分离和阶段算法；常规样式以微信开发者工具截图及真机点击验收，不只依赖构建成功。

# 5. 埋点与评估（最小化）

建议仅记录功能使用事件：成长页访问、创建开始/成功/失败、曲线指标/范围切换、历史加载更多、详情打开、阶段切换。不要上报宝宝姓名、正文、照片URL、具体身高体重或健康备注。采用家庭内匿名化标识并遵循产品已确认的数据策略。

主要评估：新增成功率、成功记录家庭占比、历史查询使用率、返回筛选保留率；方案二另观察阶段切换与历史事件回看。指标用于比较版本，不以浏览时长或儿童能力达标率作为目标。

# 6. 推荐与上线顺序

优先采用方案一：补齐测量、学习和完整历史查询，直接解决当前能力缺口。模块稳定后再将方案二作为成长页的另一种回看入口，而不是重新迁移全部记录。

1. 确认主方案、P0范围、协作权限策略、年龄与测量统计口径。
2. 设计成长主页、测量历史、事件列表、新增与详情、空/错/只读状态原型。
3. 实现接口、兼容旧记录、稳定分页和必要索引；先在测试环境验证。
4. lint、格式、类型、云函数构建、微信构建；开发者工具及真机验收。
5. 核对集合权限与索引，部署对应云函数后再发布客户端；本次只交付需求文档，未执行上述上线操作。

待评审决策：选择方案一或二；是否首版开放校园/兴趣；adult能否修改他人记录；媒体统一上限；头围与测量方法是否纳入P0。未明确的P1/P2功能默认不进入首版。
