# 成长功能实现与上线说明

本轮按已确认的「成长档案中心」最终HTML原型实现，目标为微信小程序；保持Taro原生组件与现有暖色中性设计。原始原型位于 `prototypes/growth/`。

## 已实现

- 成长Tab：身体测量 / 成长事件两个工作区，宝宝切换，加载/失败重试/空态/只读态。
- 身体测量：身长/身高、体重、头围；每项全历史最新与上次比较；独立日期范围、近3个月/6个月/1年/全部、自定义；实际月龄横轴、单点与连续趋势、点选及文字选择。
- 测量历史：沿用范围与当前指标，按月折叠，每次展示20条，支持继续展示与全开/全关。详情只有一层，不再重复跳转同一概念的页面。
- 标准参考：WS/T 423—2022附录A六张官方原表，默认P3/P50/P97、可显示全部七条，也可关闭；按档案性别、生日和测量日期匹配。只报告原表可判定区间，不计算插值百分位或Z分数。
- 身长/身高在24月龄处分开绘制，测量方法改变的实测点不连线。方法未知或不匹配、性别未填写、年龄越界、无对应整月龄节点时说明原因并保留原值。头围参考不超过36实际月龄；身高/体重不用于满84月龄及以上。
- 成长事件：P0里程碑、学习变化；近7天/30天/全部及自定义范围，类型筛选、按日期折叠、分页加载、附件计数与首个媒体展示。
- 新增/编辑：日期、时间、测量方法与来源、头围、50字事件标题、2000字描述；照片与视频合计最多10个；预览/播放、移除、上传失败后保留文字并重试或移除、上传时防重复提交；微信返回前提醒未保存内容。
- 详情：展示年龄、测量方法/来源、媒体及记录人；管理员可编辑删除任意记录，普通成员仅本人，只读不能写。使用版本条件更新，冲突不覆盖他人修改。
- 首页的「查看完整曲线」与「最近学会→查看全部」分别打开测量、事件工作区；新增后定位至对应工作区并切为全部历史以便看到补录。编辑返回保留原范围。
- 宝宝资料：补齐姓名、生日、性别的最小编辑能力，使未填写性别的旧档案能通过正常路径补全；出生日期修改前确认，并重新计算年龄与参考结果。同步补上updateChild的家庭归属和字段校验。

## 数据与兼容

继续使用 `growth_records`、`media_assets`、`children`，不新增数据库集合。

`growth_records.metrics`新增可选字段：

- `headCircumference`: cm，正数。
- `measurementMethod`: `lying` / `standing`；无身长/身高的测量可为`unknown`。旧记录不自动推断方法。
- `measurementSource`: `home` / `clinic`；旧记录未填写时显示「未记录」，不默认当作家庭测量。

`growth_records.version`：新记录从1开始，旧记录缺省按0处理，不要求批量迁移；编辑/删除必须携带读取时的`expectedVersion`，写入用版本条件保证原子性。仅前端隐藏按钮不作为权限控制。

兼容旧 `milestone + metrics.height/weight/headCircumference` 的测量记录：曲线与测量历史可读取，成长事件及首页最近学会不会重复混入。首次编辑时归一为`measurement`，需要补齐实际身长/身高方法；不会自动改旧记录的数值或时间。

本地演示模式继续用Taro storage，新增媒体用文件系统持久保存，角色与版本规则对齐。云端记录采用软删除；删除记录后会物理清理家庭与宝宝归属匹配、且没有其他有效记录引用的媒体文件，并软删除媒体元数据。共享媒体保留；清理失败以`mediaCleanupPending`标记，前端提示再次删除重试。仅编辑时移除附件不立即物理删除。

## 查询说明

新增`listGrowthRecords`：要求家庭成员身份并检查宝宝归属，按工作区、日期和事件类型返回；事件默认20条，返回标准化发生时间+ID组成的稳定游标；查询结果附带记录人、媒体类型。

由于现有库同时存在数据库Date与ISO字符串时间，该函数内部对成长类别使用ID游标按100条扫描，统一时间后再做时间排序和外部分页，避免类型混用、同时间记录分页遗漏和100条截断。全历史摘要不随日期筛选变化；测量曲线服务会读取全部页，未做静默降采样。

这沿用了当前项目的历史数据兼容策略，并非大型数据量下的最终检索方案。家庭数据增长后，建议在明确授权的数据迁移中将历史时间统一为数据库Date，再改为索引直查的时间游标；不能未经确认修改既有时间。

## 标准数据来源

`src/data/growth-standard.json`保存表A.1/A.2/A.3/A.4/A.11/A.12，共234行，包含原文地址、实施时间、来源PDF SHA256。与批准的原型数据逐项一致。

原文：https://www.nhc.gov.cn/fzs/c100048/202211/5001d7cf57774770a1d49c1df46a291f/files/1733125082501_81468.pdf

前端标准说明页支持下载并打开PDF，也可复制链接。真实环境下载原文需要在小程序后台将`https://www.nhc.gov.cn`加入downloadFile合法域名（如该域名无法配置或不可达，使用复制链接入口）。标准表随小程序代码发布，不依赖原文PDF联网成功才能绘图。

## 云端部署

先运行：

```sh
pnpm cloud:typecheck
pnpm cloud:build
```

微信开发者工具云函数目录固定为`cloud/dist/functions/`。本次需要上传的新建/更新函数：

- `listGrowthRecords`（新增）
- `createRecord`、`updateRecord`、`deleteRecord`、`getRecord`
- `getHomeOverview`（公共测量识别逻辑更新）
- `createMediaAsset`
- `updateChild`

公共模块变更已打包进各函数。应与前端同批发布；旧前端不传版本的编辑/删除调用会被新云函数以冲突拒绝，不应交错发布有写入入口的版本。

按`cloud/shared/schema.ts`在`growth_records`补充非唯一索引：

```text
idx_growth_scan: familyId ASC, childId ASC, category ASC, _id DESC
```

原有集合与记录无须删除或清空。`version`无需为旧数据批量回填。代码和云函数产物已在本地准备，不包含真实云环境上传或数据库索引创建。

使用Node 22.22.0执行 lint、format:check、前端项目类型检查（跳过第三方声明检查）、cloud:typecheck、cloud:build、build:weapp。直接`tsc --noEmit`会受到现有Taro依赖声明错误影响，未修改第三方声明或引入其他平台依赖规避它。

真实微信端仍需验证：

1. 导入最新`dist/`，上传上述云函数并配置索引。
2. 旧记录、新建仅头围、身长/身高方法变更、跨生日与自定义日期范围。
3. 标准参考开关、3/7条、点击测量点、缺少性别时从宝宝资料补全。
4. 选择9个混合媒体，再添加第10个；超限按钮禁用；重试/移除失败项；真机全屏视频与图片预览，关闭后不得重新加载页面。
5. 两个成员同时编辑同一记录，后提交者收到冲突且不覆盖；普通成员不能编辑他人，只读不能写。
6. 补录后回到成长页能看到新记录；编辑/删除后详情、列表与首页刷新；从其他页面返回时重置范围、分组和弹窗；关闭原生媒体预览时保留状态，不重新加载；切换宝宝不混入旧响应。
